# Использование FPF и его наборов DPF

Используйте публикации в этой папке для поддержки Work проекта. Указанные ниже пути задаются относительно папки, содержащей этот файл.

Когда публикация, на которую дана ссылка, присутствует в этой папке, разрешайте ссылки на её паттерны по этой локальной копии, включая ссылки, записанные как ссылки GitHub. Используйте другое издание, когда задача требует обновления или сравнения.

## Выберите, что читать

Начинайте с фактической ситуации, объекта, над которым ведётся Work, и результата, который должен поддерживать ответ. Если конкретный паттерн уже назван, найдите его напрямую. В противном случае используйте `Readme.md`, чтобы выбрать Suite или независимый DPF. В папке каждого Suite есть `README.md` для первого использования и именованный Reference для связывания вкладов: `Foundational Thinking DPF Suite/FOUNDATIONAL-THINKING-DPF-SUITE-REFERENCE.md` или `Engineering DPF Suite/ENGINEERING-DPF-SUITE-REFERENCE.md`. Ищите альтернативные формулировки вопроса; включайте английские термины, если язык пользователя отличается от языка источников.

Чтобы выполнить выбранный method, прочитайте его описание, условия применимости и связанные паттерны, необходимые для этого использования. Чтобы применить конкретную технику, прочитайте соответствующий раздел вместе с условиями, от которых она зависит. Применяйте её к фактам и ограничениям задачи.

Объясняйте результаты и давайте обратную связь на языке Work проекта. Сохраняйте различения источника, которые влияют на ответ. Ссылайтесь на использованные паттерны и места в них. Явно указывайте предположения, недостающие свидетельства, ограничения использования и необходимость человеческого суждения там, где они влияют на решение. Пусть текущий вопрос определяет следующий шаг.

Когда вопрос требует нескольких methods, используйте релевантный связанный пример или Practical-Use Card. Прослеживайте промежуточные результаты: что возвращает каждый method, какая операция использует этот результат и какое изменившееся условие возвращает Work назад. Мнемоническая формула помогает удерживать эту связь. Прочитайте паттерны, предоставляющие необходимые вклады, и начинайте с того вклада, для которого уже доступны входные данные.

## Структура файлов

Публикация содержит несколько паттернов, которые находятся по их ID. Например:

| Markdown | Значение |
| --- | --- |
| `## SYSE.24 - Choose How the Project Will Obtain a Needed Engineering Result` | Начало паттерна `SYSE.24` |
| `### SYSE.24:4 - Solution` | Раздел этого паттерна |
| `#### SYSE.24:4.1 - Name one result and one decision` | Подраздел |
| `### SYSE.24:End` | Конец паттерна |

ID также встречаются в таблицах содержания и перекрёстных ссылках. Чтобы найти сам паттерн, сопоставляйте заголовок, начинающийся с начала строки. Номера строк помогают извлекать части файла; ID позволяют находить паттерн после изменения номеров строк. Ссылка вида `SYSE.24:4.1` указывает на подраздел; читайте его до следующего заголовка того же или более высокого уровня.

## Поиск и чтение

Используйте `rg` (ripgrep) или эквивалентный инструмент поиска вашей среды с поддержкой регулярных выражений. Выполняйте эти команды, используя эту папку как рабочий каталог, либо добавляйте её фактический путь перед аргументами файлов.

Найдите записи Reference для «получить требуемый инженерный результат: сделать или купить»:

```sh
rg -n -i -C 2 'buy|build|obtain the result' -- "Engineering DPF Suite/ENGINEERING-DPF-SUITE-REFERENCE.md"
```

Найдите файл, а также строки начала и конца выбранного паттерна:

```sh
rg -n --no-ignore -g '*.md' '^## SYSE\.24 |^### SYSE\.24:End[ \t]*\r?$' -- .
```

Прочитайте этот паттерн полностью:

```sh
rg -U --no-heading --no-line-number --no-filename --color never '(?ms)^## SYSE\.24 [^\r\n]*\r?\n.*?^### SYSE\.24:End[ \t]*\r?$' -- "Engineering DPF Suite/SYSTEMS-ENGINEERING-PRINCIPLES-FRAMEWORK.md"
```

Здесь `-U` включает многострочный поиск; `(?m)` заставляет `^` и `$` соответствовать началу и концу строк, а `(?s)` позволяет точке соответствовать переводу строки. `(?ms)` объединяет оба режима. `.*?` сопоставляет текст до ближайшего указанного заголовка `:End`; `\r?\n` допускает окончания строк Windows и Unix. При необходимости подставьте другой ID и файл; экранируйте литеральные точки в ID как `\.`.

Для других поисков `-F` трактует запрос как буквальный текст, `-i` игнорирует регистр, а `-C 2` включает соседние строки. `--no-ignore` ищет файлы даже в папке, игнорируемой Git; `-g '*.md'` выбирает Markdown-файлы.

Если инструмент обрезает длинный результат, читайте выбранный текст последовательными диапазонами строк с помощью доступного средства чтения файлов. Поиск по папке уже охватывает отдельные публикации; объединённый файл не требуется.
