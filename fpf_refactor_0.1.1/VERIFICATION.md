# Проверка 0.1.0-rc.1

Среда внутренней проверки: Linux, Node.js 24.19.0; Firebase CLI 13.35.1, Realtime Database Emulator 4.11.2, Java 17; Playwright 1.51.1 / Chromium 134.0.6998.35.

## Подтверждённые уровни

- `evidence/unit.tap`: 17 успешных проверок предметного ядра и серверной границы на SQLite; 0 ошибок.
- `evidence/rtdb-run.log`: 13 успешных проверок с реальным RTDB Emulator; 0 ошибок. Повторяет 11 контрактных случаев на другом хранилище и добавляет отказ прямой записи/чтения и запрет production-конфигурации адаптера.
- `evidence/browser.json` и `browser-run.log`: 28 успешных контрольных точек полного UI-прогона в режимах server и demo. Итоговый счётчик указан в журнале; это последовательные проверки сценариев, не независимые статистические испытания.
- Снимки `evidence/server-*.png`, `demo-*.png`: Chromium, ширина 390 и 768 CSS px. Проверено отсутствие горизонтального переполнения; визуально осмотрены экраны 390 и 768 px.
- До упаковки проверены синтаксис JS-модулей, разрешимость локальных импортов, CRC ZIP и соответствие файлов manifest.

Браузерный сценарий создаёт Team через UI, ведёт две партии, проверяет blank/zero, отказ сохранения очка и завершения, reload/Undo, отключение связи и восстановление, потерю ответа после фактического принятия, повтор передачи, Team Undo, новую попытку, блокировку второго автора и другого Team-контекста. Ошибки страницы собираются и проверяются. CSP приложения не отключается в итоговом прогоне.

Ошибки хранения/связи инъецируются предусмотренными переключателями: отказ настоящей IndexedDB-транзакции; блокировка запросов транспортного адаптера; отбрасывание ответа уже исполненной команды. Это не испытание аппаратного отказа накопителя или радиоканала. Race-тесты делают восемь параллельных повторов команды и конкурирующие manual/automatic обращения к одному агрегату.

## Воспроизведение

Для runtime зависимости не нужны (`node server/http.mjs`). Для тестов установите инструменты:

```sh
npm ci
npx playwright install chromium
npm test
npm run test:rtdb
npm run test:browser
```

RTDB проверяйте через `emulators:exec` из npm-скрипта: он запускает эмулятор и тесты в одной среде. Java нужна только для эмулятора. Сетевые загрузки npm/браузера/эмулятора могут требовать доступа к соответствующим серверам. Firebase CLI 13.35.1 в данной среде работал на Node 24; одна его необязательная транзитивная зависимость superstatic сообщает о поддержке Node 18/20/22. Используемый database-only прогон прошёл; совместимость прочих команд CLI не заявляется.

Переменные `TTS_PLAYWRIGHT` и `PLAYWRIGHT_BROWSERS_PATH` в тесте позволяют использовать отдельно установленный Playwright и его браузер. Обычный `npm ci` этого не требует. Тесты создают временные Team и SQLite in-memory, не обращаются к действующему облачному проекту.

## История исправления и непрошедшие прогоны

- `evidence/rtdb.tap` — прежний неуспешный запуск: порт эмулятора был недоступен из отдельной изолированной команды. Он не является итоговым RTDB evidence. Устранено запуском в одном окружении через `emulators:exec`; итог — `rtdb-run.log`.
- `evidence/browser-before-fix.log` — первая ошибка UI: заблокированная вторая вкладка попадала на сообщение об отсутствии Team-данных. Исправлен порядок отображения блокировки; итоговый прогон включает этот случай.
- Первая попытка browser harness с `waitForFunction` столкнулась с CSP из-за eval самого тестового инструмента. Итоговый harness опрашивает через `page.evaluate`, не меняя CSP runtime. Она не выдаётся за дефект игрового приложения.

## Не подтверждено

Реальные Safari iOS/iPadOS, Comet, несколько физических устройств, мобильная потеря сети, работа после выгрузки вкладки ОС, production Firebase, настройка HTTPS принимающего сервера и длительная эксплуатация. Эти пункты не заменены эмулятором или viewport Chromium. Внешняя приёмка — по `ACCEPTANCE.md`.
