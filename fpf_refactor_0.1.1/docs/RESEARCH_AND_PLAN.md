# Исследование и выполненный план

Основания — два документа в `docs/design/` и предоставленный ttScore Suite 0.4.0-rc.8. Исходные ZIP: FPF SHA-256 `1615e5bde6375446e163fcfecc191da63f54af12cb07ef5eba1589c312dcf9f5`; Suite SHA-256 `3e75b114db103367be8732bbf8cb737454f092a45328aeed4e8b520408f1ce20`.

1. Закреплены типы, фазы, отдельные показания и спортивный итог, binding, immutable completion и command receipts.
2. Реализована доверенная серверная граница и два постоянных адаптера. Причина выбора и trade-offs — ARCHITECTURE_DECISION.md.
3. Реализован браузерный счётчик, сохранение и минимальные роли. Дополнительно сделана статическая single-browser демонстрация для доступного теста на iPad.
4. Проведены предметные тесты и RTDB race/retry/authorization проверки; затем реальные UI-прогоны Chromium в двух режимах.
5. Исправлены сообщение о блокировке второго Umpire, сохранение истории Undo при неуспешном commit, лишняя повторная публикация одинаковой ревизии, устаревшее сообщение после подготовки новой сессии, выдача заголовка 200 до чтения статического файла и проверка чужого активного Team-контекста между ролями. Не для каждого раннего статического исправления существует отдельный failing test; итоговый UI-прогон проверяет значимые пользовательские ветви.
6. Сформирован полный кандидат и отдельный пользовательский сценарий приёмки.

Во время первого этапа окружение отключалось. Записанные исходники сохранились; результаты последних тестов были прочитаны и повторены после восстановления. Неполные прогоны не названы успешными.

Следующий этап после полевой проверки этого кандидата: исправить обнаруженные расхождения в Safari, завершить облачное размещение отдельного тестового сервиса по выбранной модели полномочий, затем расширять функциональность до RC8. Текущая работа не изменяла старое развёртывание.
