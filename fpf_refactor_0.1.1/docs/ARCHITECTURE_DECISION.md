# Решения реализации прототипа

## Граница и размещение

Разработка выполнена с нуля по `docs/design/`. Первая проверяемая часть ограничена последовательной 2×2: по четыре спортсмена, четыре пары, bestOf 3/5/7. Остальные функции функционального контракта RC8 не объявляются реализованными.

SCORE/FLOW реализованы в `domain.mjs`; `authority.mjs` задаёт чистое по состоянию выполнение команд с проверкой полномочий, identity, канонического JSON, SHA-256 и результата по розыгрышам. IndexedDB (`storage.mjs`) сохраняет сессию и CompletionEnvelope одним объектом в одной транзакции, с compare-and-swap по версии. Розыгрыши вводятся независимо от сети. Предыдущий снимок хранится для одного durable Undo, дополнительные до 50 — в памяти.

Архитектурное уточнение: принятие перенесено в доверенный обработчик `server/service.mjs`. RTDB Rules закрывают клиентские чтение/запись, а обработчик проверяет отчёт и условно записывает целый агрегат Team. Это выбранная ограниченная реализация предусмотренной запасной ветки; мы не доказывали, что никакая более сложная схема Rules не способна реализовать эквивалентный протокол. Проверка SHA-256/декодирования отчёта на сервере делает эту границу явной.

Два постоянных серверных адаптера: SQLite CAS для автономного запуска сервера и RTDB REST ETag CAS для локального эмулятора. В RTDB агрегат сохранён как JSON-строка в `body`, чтобы сохранить null, пустые словари и массивы без изменения смысла. Цена: целый агрегат с отчётами читается и записывается при изменении; для массовой эксплуатации требуется отдельная работа по размерам и разделению данных.

Историческая квитанция проверяется до актуальности current: повтор принятого запроса возвращает прежний исход, а после Undo — `accepted_then_undone`. Для нового эффекта требуется полное совпадение binding. Ручной и автоматический результат конкурируют за один CAS. Квитанция не является действующей победой. Результаты считаются из текущих записей результатов встреч.

Техническое право роли — случайная capability-ссылка; хеши хранятся в принимающем агрегате, токен передаётся HTTP Authorization, первоначально переносится во fragment URL и убирается из адресной строки. Это модель доступа прототипа, не Firebase Auth и не идентификация человека. Прямые публичные данные не содержат токены/хеши/байты отчётов. Полноценное управление сроком и отзывом capability-ссылок — следующий этап перед размещением сервера в интернете.

## Режим демонстрации

Статический `public/config.mjs` выбирает `demo`: та же логика команды выполняется браузером, агрегат Team хранится в общей IndexedDB. Это удобный вариант для проверки UI на iPad через HTTPS, но не доверенная граница. Владелец браузерного хранилища может менять данные. Разные устройства/браузеры не синхронизируются.

Node-сервер переопределяет `/config.mjs` на `server`; браузер вызывает API. Сервер привязан к 127.0.0.1. RTDB-адаптер дополнительно отвергает production URL и namespace без `demo-`. Никаких ключей рабочего Firebase или миграции действующего продукта нет.

## Явные ограничения решения

При отказе локальной записи команда отклоняется с сохранением прежнего счёта; аварийное продолжение в volatile-памяти из большой архитектуры пока не реализовано. Это более узкое поведение прототипа, а не заявленная эквивалентность RC8. Начальные условия упрощены: первый подающий выбирается; стороны меняются вручную/между партиями, автоматического предложения при 5 в решающей партии пока нет.

Имена, определения и карта изменений — в приложенной предметной модели. Реализация пока не покрывает все её ветви и самостоятельный счётчик вне Team. Статусы доставки и ревизии, применённые здесь, служат первому сквозному сценарию.

## Технические основания

- Условия доступа и проверки данных RTDB: [Firebase Rules conditions](https://firebase.google.com/docs/database/security/rules-conditions).
- Demo-проекты и соединение с эмулятором: [Realtime Database Emulator](https://firebase.google.com/docs/emulator-suite/connect_rtdb).
- Условные REST-записи с ETag/If-Match: [Saving data](https://firebase.google.com/docs/database/rest/save-data).

Документация проверена при реализации; вывод о выбранной конструкции — наше проектное решение, а не обещание провайдера о всём приложении.
