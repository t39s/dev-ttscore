# ttScore prototype 0.1.0-rc.1

Сквозной прототип нового приложения: командная встреча **2×2**, четыре личные встречи из 3/5/7 партий; роли Administrator, Umpire и зритель. Это кандидат для проверки, не замена ttScore Suite RC8.

## Быстрый запуск на iPhone/iPad

1. Распакуйте архив.
2. Загрузите **всё содержимое `public/`** в отдельную папку своего HTTPS-сайта (например, GitHub Pages). Сохраните имена восьми файлов и их соседство.
3. Откройте адрес этой папки в Safari. Для Koder подойдёт HTTP-адрес `localhost`, если сервер отдаёт `.mjs` как JavaScript. Открытие `index.html` через «Файлы»/`file://` не поддерживается.
4. Создайте встречу. Нажмите «Открыть Umpire»; табло можно открыть в соседней вкладке. Для возврата используйте ссылки ролей приложения.

**В этом режиме все роли должны находиться в одном браузере, профиле и адресе сайта.** Данные лежат в IndexedDB. Safari и Comet, разные устройства или частная/обычная вкладки не обмениваются ими. Сервер и Firebase не нужны. Это локальная демонстрация интерфейсов и протокола, не облачная проверка. Рабочие файлы прежнего ttScore не заменяйте.

## Запуск принимающего сервера на компьютере

Нужен Node.js 24 или новее. В терминале откройте корень распакованного проекта:

```sh
node server/http.mjs
```

Откройте `http://127.0.0.1:8787/` на этом компьютере. Runtime использует только встроенные модули Node; `npm install` для запуска не нужен. В этом режиме правила проверяются сервером, данные Team сохраняются в `data/prototype.sqlite`, локальный счёт — в браузере. Допустимы разные браузеры на одном компьютере: передавайте ссылку Umpire из «Ссылки ролей», зрителю — публичную ссылку. Сервер слушает только loopback; доступ с iPhone/iPad к нему не настроен. SQLite-файлы пользователя в архив не включены.

## Короткая проверка

1. «Подготовить встречу» → «Спортсмены прибыли» → «Начать партию».
2. Нажимайте зоны спортсменов. Между партиями отдельно подготовьте и начните следующую.
3. После финала цифры удерживаются; можно выполнить Undo до подтверждения. Затем «Подтвердить завершение» — Team получает одну победу.
4. В Administrator выполните Team Undo. Повторная синхронизация старого счётчика не должна вернуть победу.
5. В разделе «Проверка восстановления» доступны отключение связи, отказ следующего сохранения и потеря ответа о принятии. Подробный сценарий — `ACCEPTANCE.md`.

## Состав и пределы

- `public/` — весь браузерный runtime; `server/` — доверенный обработчик и SQLite/RTDB-адаптеры.
- `tests/`, `evidence/` — тесты, сохранённые результаты и снимки экрана.
- `docs/` — контракт, решения, ревью, исходные архитектура и предметная модель этой работы.
- `VERIFICATION.md`, `KNOWN_ISSUES.md`, `DECISION.md` — границы подтверждённых результатов и дальнейшие действия.
- `MANIFEST.sha256` — контрольные суммы файлов поставки.

Рабочее облако не подключено и не изменено. RTDB-адаптер разрешает только локальный demo-эмулятор; его проверка описана в `VERIFICATION.md`. На реальных iPhone/iPad этот кандидат ещё не принят. Отчёт пока экспортируется только в собственный JSON прототипа; это не совместимый импорт RC8. Фора, озвучивание, 3×3/4×4, полноценные отчёты и защищённые файлы оставлены следующему этапу.
