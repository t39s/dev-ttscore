# Известные ограничения 0.1.0-rc.1

Единый реестр ограничений текущего кандидата. Ошибка сообщения второй вкладки устранена, подтверждена повторным сценарием. Непроведённые полевые проверки перечислены отдельно в VERIFICATION.md.

## P-001 — При отказе IndexedDB счётчик отклоняет действие

- Сценарий: локальная транзакция не может быть сохранена.
- Severity: MEDIUM; Likelihood: не измерена; Exposure: сценарий отказа storage; Recoverability: повторить действие после восстановления либо сохранить доступный отчёт; Product risk: MEDIUM для реального судейства.
- Decision: DEFER для ограниченного прототипа.
- Rationale: сохраняется последний подтверждённый счёт и видимое сообщение об отказе; нет скрытой публикации несохранённых очков. Продолжение в volatile-памяти из полной архитектуры пока отсутствует.
- Return condition: до заявления полного соответствия RC8 реализовать и испытать аварийный режим.

## P-002 — Доступ по capability-ссылке не имеет полноценного управления отзывом

- Сценарий: ссылка управления передана нежелательному получателю.
- Severity: HIGH; Likelihood: не измерена; Exposure: передача приватной ссылки; Recoverability: тестовую Team можно заменить, отзыв отдельной capability пока не реализован; Product risk: LOW в изолированном тесте, HIGH для публичного рабочего сервера.
- Decision: DEFER.
- Rationale: серверный запуск ограничен loopback; runtime не поставляется как защищённая облачная служба. Отзыв регистрации счётчика не равен отзыву capability-роли.
- Return condition: перед публикацией сервера в интернете реализовать управление полномочиями, отзыв и эксплуатационные ограничения API.

## P-003 — Целый серверный агрегат содержит историю и отчёты

- Сценарий: множество попыток/Undo/отчётов накапливается в одной Team.
- Severity: MEDIUM; Likelihood: возрастает с числом повторов, не измерена; Exposure: длительное повторное использование Team; Recoverability: новая тестовая Team и сохранённые отчёты; Product risk: LOW для четырёх обычных личных встреч прототипа.
- Decision: DEFER.
- Rationale: общий CAS делает атомарность наглядной; нагрузочное поведение и ограничение суммарного размера не исследованы.
- Return condition: до масштабирования выделить хранение больших артефактов и проверить границы транзакций/размеров.

## P-004 — Локальный архив не имеет отдельного экрана просмотра

- Сценарий: после подготовки следующей сессии нужно повторно скачать отчёт предыдущей.
- Severity: LOW; Likelihood: возможно в обычном тесте; Exposure: переход к следующей встрече; Recoverability: заранее скачать JSON, сохранённые записи остаются в IndexedDB; Product risk: LOW для текущего прототипа.
- Decision: DEFER.
- Rationale: UI показывает текущую/непосредственно завершённую сессию, но отдельный просмотр всех архивных записей не реализован. Не полагаться на скрытый архив как на пользовательский резервный носитель.
- Return condition: этап полноценных отчётов и экспорта.

Отсутствующие возможности (3×3/4×4, standalone, фора, TTS, форматы RC8) — явная граница этапа, а не объявленные выполненными функции. Для обычной эксплуатации продолжайте использовать принятую версию ttScore Suite.
